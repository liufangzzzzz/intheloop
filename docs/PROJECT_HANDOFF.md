# In The Loop 官网交接说明

更新日期：2026-11-12  
适用对象：新电脑上的 Codex、后续开发者和设计人员

完整产品与运营逻辑以兄弟仓库的 `../jk-toolkit-intheloop/docs/PROJECT_HANDOFF.md` 为首要参考。本文件说明官网自己的职责和不能被改坏的展示规则。

## 1. 仓库职责

本仓库 `Geekpark-hub/intheloop` 是 In The Loop 中英文对外官网。

```text
中文：https://intheloop.geekpark.net/zh
英文：https://intheloop.geekpark.net/en
```

运营工作台、FastAPI 后端、SQLite 数据、AI 处理和发布接口位于 `Geekpark-hub/jk-toolkit-intheloop`。两个仓库分别部署。官网通过 `INTHELOOP_CONTENT_API_ORIGIN` 指向的公开 API 读取已发布快照，不直接读取草稿。

## 2. 主要路由

```text
/zh
/en
/zh/launch/{slug}
/en/launch/{slug}
```

首页通过查询参数展示文章、标签、播客聚合和不同栏目。专题地址中的 `{slug}` 由运营在工作台填写，不是固定的 `fable-5-2`。

## 3. 中文首页

中文栏目为：最新内容、精选内容、深度对话、海外观察。

桌面端当前栏目是主要标题，其他栏目是旁边入口。手机端当前栏目占左侧大区域，另外三个栏目在右侧纵向排列；切换后新的当前栏目成为大区域，不能把其他栏目表现成“最新内容”的下级。

中文站还有站内播客聚合页。页面顶部展示“开始连接 LinkStart”的图标、二维码和跳转入口，下面按时间倒序展示带播客标签的内容。

中文站应当年轻、鲜活、有“正在现场”的感觉。以黑白为主体，Lover 渐变色作为边框、状态和运动线索。中文正文使用可商用、较轻的宋体气质，避免沉重、老式或大面积圆角卡片。

## 4. 英文首页

英文栏目为 Featured、Latest、Conversations。

英文站保持安静、克制、编辑部式的视觉气质，不照搬中文站的高能量设计。英文站不展示小宇宙入口；具有英文 transcript 的播客可以作为 Conversations 内容出现。

## 5. 地图与标签

标签分为内容类型、实体和技术主题。旋转地图主要展示运营选中的技术主题，也允许少数重要实体进入。

- 地图的大、中、小只是视觉级别，不是数据库父子层级。
- 技术主题支持任意深度父子关系。
- 点击普通地图标签进入该标签页面。
- 如果该标签临时关联了已发布专题，点击可以进入专题页。
- 内容只因直接关联标签而出现，不能自动继承公司关联的全部技术主题。
- 中文地图可以更活跃；英文地图保持现有较轻、较慢的运动感。

标签页可以展示主题介绍、人工精选、全部直接相关内容、关联公司和子主题。

## 6. 发布快照与内容显示

- 官网只显示已经发布的中文或英文快照。
- 中文和英文可以分别发布、更新或下线。
- 海外观察只在中文站显示。
- Latest 和 Featured 是展示状态，不是技术标签。
- Featured 的中文和英文顺序分别管理。
- 普通内容、深度对话、播客和海外观察可以重叠出现。
- 日期允许只有年份、年月或完整年月日；排序需要兼容不完整日期。

## 7. 正文媒体

文章中的图片、GIF 和视频来自工作台持久化媒体接口。

- 媒体应按源文章位置自动出现在正文中。
- 官网必须正确处理公开媒体 URL，不依赖工作台登录态。
- 不要只在预览中显示而漏掉发布后的正文。
- 图片失败时显示合理的替代文字，不能让整篇文章崩溃。
- 后端媒体路径或域名改变时，两个仓库要一起验证。

## 8. 专题 HTML

专题用于快速发布一次模型、产品、公司或事件的独立资料页。

- 地址为 `/zh/launch/{slug}` 和可选的 `/en/launch/{slug}`。
- 中文专题默认套用中文站页头页尾，也可以选择完整独立 HTML。
- 英文展示默认关闭。
- 专题可以关联标签、成为临时地图入口，并显示站内延伸阅读。
- 热度过去后只移除地图入口，专题 URL 继续存档。
- 当前上传格式以单个 HTML 为主；资源应使用 HTTPS 绝对地址或内嵌 data URL。

## 9. 搜索与统计

官网已经接入 Google Search Console 验证、GTM 和 GA4。修改页面框架时保留相关代码，并检查 `/zh`、`/en`、文章页、标签页和专题页都能被统计。

SEO 需要继续保证稳定 URL，正确的标题、描述、canonical 和语言信息，服务端可读取的正文，以及文章、标签和专题之间的真实站内链接。

## 10. 修改检查

修改前：

1. 阅读本文件和工作台的完整交接说明；
2. 确认变化是否同时需要修改后端公开 API；
3. 检查工作区是否有用户未提交的修改。

修改后：

1. 运行 TypeScript 检查和生产构建；
2. 检查中文和英文桌面端；
3. 检查手机端当前栏目与其他栏目的层级；
4. 检查文章、标签、播客、媒体和专题路由；
5. 除非用户明确要求，不要推送或部署。

当前首页代码较集中。可以逐步拆分稳定组件，但不要为“技术整洁”一次性重写页面，避免破坏已经确认的中文和英文交互差异。
